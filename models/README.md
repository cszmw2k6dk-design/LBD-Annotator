# 模型包：LBD-yolo26n-2560

在 CAD 电气图纸上检测两类目标，给标注工具的「用模型识别」用。

| 文件 | 说明 |
| --- | --- |
| `best/LBD-yolo26n-2560.pt` | 权重（yolo26n，5.6 MB） |
| `best/classes.txt` | 类别：`Node` / `Tracker`（标注工具会自动读同目录的这个文件） |
| `best/meta.txt` | 训练参数，其中 **imgsz=2560** —— 工具选模型时会自动读它填好 imgsz |
| `v4c/LBD-yolo26n-2560-v4c.pt` | **新版权重（2026-10-08）**：老图纸 + 新数据（Steel River/Bigway/Highland）一起训的 30 轮版，比上面那版略好，详见下面「v4c 版」 |
| `v4c/classes.txt`、`v4c/meta.txt` | 同上，类别 Node/Tracker、imgsz=2560 |

## v4c 版（2026-10-08 上传）

`v4c/LBD-yolo26n-2560-v4c.pt`（5.6 MB）= `runs\detect\yolo26n_2560_v4c` 第 28 轮的 best，
数据是 **dataset_v4：1,545 页 / 226,211 框**（老图纸 + Steel River + Bigway + Highland），
imgsz 2560、batch 4、lr0 0.0005、cos_lr、30 轮（2026-10-02 开跑，中途两次断点续训，10-08 凌晨跑完）。

**干净验证集**（215 页，已剔掉 Moss-Driver / Moss-Sabal Palm 那两套"两根板条合成一框"的图纸）
实测，和上一版对比：

| 版本 | 总 P | 总 R | mAP50 | mAP50-95 |
| --- | --- | --- | --- | --- |
| 旧版 `best/LBD-yolo26n-2560.pt` | 0.955 | 0.973 | 0.987 | 0.819 |
| **v4c** | **0.960** | **0.977** | **0.989** | **0.825** |

分类别（v4c）：Node P 0.957 / R 0.975 / mAP50-95 0.832；Tracker P 0.964 / R 0.979 / mAP50-95 0.817。

**用的时候参数这样填**（比拼指标时更明显）：

- **imgsz 2560**（和训练一致，不要放大到 3200 —— 实测反而更差）
- **conf 0.35**（0.25 误检多、0.45 起漏检变多）
- **NMS IoU 0.4**（关键：旧默认 0.7 几乎不去重，同一根板条出两个重叠框全算误检；
  实测旧图纸 Tracker 精确率 **0.908 → 0.981**、新数据 0.886 → 0.951）
- 标注工具 v0.39 起这三个值已经是默认值，`max_det` 也放到了 1000（板条超过 300 根的页不再被截断）

**已知的正常现象**：Moss-Driver、Moss-Sabal Palm 这两套图纸的标注是"相邻两根板条合成一框"，
和模型的"每根一框"口径不一致，所以在它们上面会看到大量"误检"（IoU 只有 0.41~0.44）——
这是标注口径问题，不是模型坏了，统一口径后即可。

## 性能

验证集 155 张图 / 14,047 个框（按图纸分组切分，train 与 val 无同图泄漏）：

| 类别 | P | R | mAP50 | mAP50-95 |
| --- | --- | --- | --- | --- |
| 全部 | 0.908 | 0.941 | **0.983** | **0.846** |
| Node（阵列块） | 0.861 | 0.990 | 0.983 | 0.830 |
| Tracker（板列） | 0.955 | 0.892 | 0.982 | 0.862 |

## 怎么用

标注工具 →「用模型识别」→ 选 `best/LBD-yolo26n-2560.pt`：

- **imgsz 填 2560**（选模型时工具会按 `meta.txt` 自动填好）
- **conf 填 0.25~0.4**：0.4 时误检最少，0.25 时漏检最少（Tracker 召回 0.87 → 0.95）
- 「识别后清理多余框」保持勾选

## 训练过程

三轮串联，共 125 轮，全部在 CPU 上跑：

| 阶段 | 配置 | 结果（mAP50 / mAP50-95） |
| --- | --- | --- |
| 1 | yolo26n，imgsz 1920，60 轮 | 0.937 / 0.772 |
| 2 | 从阶段 1 的 best 微调，imgsz 1920，40 轮 | 0.930 / 0.775 |
| 3 | 从阶段 2 的 best 微调，**imgsz 2560**，25 轮 | **0.983 / 0.846** |

数据：718 张标注图纸（同一张图纸的高/低分辨率重复版本已去重）、76,752 个框，
训练集按图纸分组切分。

**为什么提分辨率有效**：Tracker 在 imgsz 1920 下只有约 5 个像素宽，提到 2560 后
约 6.8 像素，两个指标都明显上涨，Tracker 的准确率从 0.779 升到 0.955。

## 注意

- 推理前**必须把渲染图平滑缩放到长边 2560** 再喂模型。直接把 9000×6000 丢进去，
  ultralytics 内部会用 cv2 的一步线性插值降采样，细线（板列）会被"跳过"，
  Tracker 召回实测从 0.68 掉到 0.44。标注工具里已经内置了这一步。
- 本仓库**不含训练数据**（图纸与标注属客户资料，不入库）。
- 这个模型是从客户图纸训练出来的，对外分发前请先确认公司和客户那边没有限制。
